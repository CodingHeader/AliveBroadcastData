## 1. `server/models.py`

### 文件级目标
补齐多维导入所需的数据承载能力、导入批次审计能力、重复跳过记录能力，为后续解析和去重提供落库基础。

- `Lead`
- `ApiClue`
- `SchedulePlan` / `ScheduleSlot` / `ScheduleBinding`
- `ClueAssignment`
- 少量与现有线索业务相关的表

但**没有**能完整承载以下业务的结构：
- 教育在线
- 抖音代运营
- 朋友圈广告
- 直播数据分配
- 直播排班
- 导入批次日志
- 重复跳过明细

### 文件级检查对象
- `Lead`
- `ApiClue`
- `SchedulePlan`
- `ScheduleBinding`
- `ClueAssignment`
- 现有 `Base` 模型注册区

### 文件级执行方法
- 设计新模型或扩展现有模型字段
- 明确多维导入数据落到哪张表
- 为“联系方式 + 微信”去重准备可比较字段
- 为导入批次和重复跳过增加日志承载

### 文件级预期
- 多维数据有明确落库对象
- 重复导入有审计对象
- 管理员可查询重复跳过情况

### 文件级异常分支

- 若不新增批次日志，就无法回答“哪些被跳过”

### 文件级判定标准
- 能从数据库层回答：
  1. 这条数据属于哪类表
  2. 这条数据是否重复
  3. 这次导入跳过了什么

## 1. `server/routers/admin.py` → `upload_excel_clues()`

### 函数级目标
从“只处理 active sheet 的线索导入”升级为“多 sheet、多类型、多格式的预览解析入口”。

### 当前事实问题
现状是：
- `load_workbook(...)`
- `ws = wb.active`
- 只读取少量固定列名
- 仅生成用于 `ApiClue` 的极简预览结构

这无法满足：
- 多 sheet
- 自动分类
- 真实表头漂移
- CSV 支持
- 重复预判

### 函数级检查对象
- `wb.active`
- `wb.sheetnames`
- 表头识别逻辑
- sheet 类型识别逻辑
- 文件格式分支逻辑
- 返回 JSON 结构

### 函数级执行方法
1. 先识别文件类型：xlsx / xls / csv
2. 对 xlsx 遍历全部 sheet
3. 对每个 sheet 提取表头
4. 对表头做标准化
5. 做 sheet 类型识别
6. 根据类型走不同解析器
7. 返回按 sheet 分组的预览数据、错误、重复候选

### 函数级预期
- 一个合并文件能返回多个 sheet 的解析结果
- 每个 sheet 都有类型信息
- 能判断哪些 sheet 可导入
- 能预览哪些记录可能重复

### 函数级异常分支
- 如果文件打不开，需要记录为“解析失败”
- 如果某 sheet 为空，跳过并记录 warning
- 如果 sheet 类型不明，标记为 unknown 并提示人工确认
- 如果表头不完整，进入错误分支而不是静默丢弃

### 函数级判定标准
- 返回体必须包含：
  - `sheets`
  - `summary`
  - `errors`
  - `duplicates_preview`
  - `sheet_type`
- 不能再只是一个扁平 `results` 数组

## 2. `server/routers/admin.py` → `confirm_excel_import()`

### 函数级目标
从“逐条新增 ApiClue”升级为“按 sheet/按类型确认落库，支持重复跳过、导入日志、批次统计”。

### 当前事实问题
现状是：
- 直接 `for item in items`
- 直接创建 `ApiClue`
- 无查重
- 无跳过
- 无审计
- 无批次记录

### 函数级检查对象
- 入参结构
- 去重判断
- 写入目标表
- 导入日志结构
- 返回统计结构

### 函数级执行方法
1. 接收前端确认的 sheet 分组结果
2. 根据 sheet 类型路由到对应落库逻辑
3. 对每条记录做标准化
4. 以“联系方式 + 微信”作为去重键
5. 命中重复则写入跳过记录
6. 非重复则入库
7. 记录批次日志
8. 返回导入统计

### 函数级预期
- 同一记录第二次导入时不会再次新增
- 重复条数被准确记录
- 管理员能看到跳过原因
- 导入成功与重复跳过可分开统计

### 函数级异常分支
- 如果某条记录缺少联系方式和微信，则不能直接判定为唯一记录
- 如果某表没有微信列，要进入降级去重策略
- 如果某 sheet 类型不明，不应强制落库，应提示管理员确认

### 函数级判定标准
- 导入完成后，必须能得到：
  - 新增多少条
  - 跳过多少条
  - 哪些重复
  - 哪些错误
  - 哪些 sheet 成功

# 三、原子任务级最终执行清单

下面把每个函数再拆成最小原子任务。  
这部分是你要求的“最终不能再细分”的层级。

## A. `server/models.py` 原子任务

### A1. 新增导入批次日志模型
- **目标**：记录每次导入整体情况
- **检查对象**：是否存在导入批次表
- **方法**：定义批次ID、文件名、sheet名、总数、新增数、跳过数、错误数、创建时间
- **预期**：每次导入可追踪
- **异常分支**：若无批次日志，导入结果不可审计
- **判定标准**：任意一次导入都可回溯到记录

### A2. 新增重复跳过明细模型
- **目标**：记录重复项
- **检查对象**：是否存在重复明细表
- **方法**：记录联系方式、微信、sheet名、重复原因、原始行内容、批次ID
- **预期**：管理员可查看重复记录
- **异常分支**：若仅有总数无明细，无法查看被跳过项
- **判定标准**：每条重复都可查询

### A3. 为业务数据增加归一化比较字段
- **目标**：支持稳定去重
- **检查对象**：联系方式、微信、去重键字段
- **方法**：增加标准化字段或虚拟唯一键
- **预期**：相同业务身份可稳定比较
- **异常分支**：空格、格式差异导致去重失效
- **判定标准**：同一联系人不会因格式差异重复入库

### A4. 为多维数据增加承载字段
- **目标**：避免业务维度丢失
- **检查对象**：学历、学校、专业、招生老师、跟进、状态标签、投放账户、单元信息等
- **方法**：按真实 sheet 字段补模型
- **预期**：导入信息完整保留
- **异常分支**：字段太少，业务维度被吞掉
- **判定标准**：示例表中的核心字段都能落库

## B. `server/routers/admin.py` 原子任务

### B1. `upload_excel_clues()` 支持多文件格式识别
- **目标**：识别 xlsx / csv / xls
- **检查对象**：文件扩展名和解析分支
- **方法**：按扩展名选择解析器
- **预期**：CSV 不再被拒绝
- **异常分支**：扩展名判断失败导致解析器错误
- **判定标准**：同一入口能处理三类文件

### B2. `upload_excel_clues()` 遍历所有 sheet
- **目标**：不再只看一个 active sheet
- **检查对象**：`wb.active`
- **方法**：改为遍历 `wb.sheetnames`
- **预期**：所有 sheet 都进入解析
- **异常分支**：空 sheet 被误解析
- **判定标准**：多 sheet 文件全部可见

### B3. 增加表头标准化函数
- **目标**：解决表头有空格、别名、大小写差异
- **检查对象**：表头字符串
- **方法**：去空格、统一大小写、统一符号
- **预期**：同义列能命中
- **异常分支**：不标准化会导致别名识别失败
- **判定标准**：列名变体仍能识别

### B4. 增加 sheet 类型识别函数
- **目标**：按列名自动区分工作表
- **检查对象**：表头特征集合
- **方法**：对教育在线、抖音代运营、朋友圈广告、直播排班、直播数据分配做指纹匹配
